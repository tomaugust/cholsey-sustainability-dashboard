## Done

- Created `pipeline/tests/golden/` (`golden_values.py`, `test_golden_values.py`).

  - **Greenspace**: independently fetched Cholsey's real BFC parish polygon (`geography.boundaries.fetch_boundary`) and the cached OS Open Greenspace raw zip (`fetch.os_open_greenspace.fetch_greenspace_sites`, no re-download — conditional GET against the already-cached file), then wrote a standalone `geopandas.clip` + accessible-function-type filter + area sum (not calling `metrics.greenspace.compute_subject_greenspace_row`). Result: 89,089.84030000071 m² accessible / 4,404 residents = 20.2293007039057 m²/resident — an exact match to the committed `metrics.csv` value.
  - **Electricity/gas**: independently re-read the real 2024 LSOA-level DESNZ workbooks' raw rows (`openpyxl`, direct) for Cholsey's three contributing LSOAs, and redid the apportionment by hand using the real P1.5 address weights (1.0, 1.0, 0.583234) and the Σconsumption/Σmeters formula `metrics/energy.py`'s own docstring documents. Both independently computed means (3682.271410334187 kWh/meter/year electricity, 11000.805698360531 gas) matched the committed `metrics.csv` values exactly.
  - **Heat pump/solar PV**: direct read of MCS's own committed export CSVs (2.73%, 10.08%) — no arithmetic, per ADR-0007's uniform-rate-applied-unchanged method.
- Added a second test (`test_every_built_metric_has_a_golden_value`) catching the inverse mistake — a metric added to `metrics.csv` with no golden value ever added for it.
