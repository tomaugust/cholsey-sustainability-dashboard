- **P2.2 — generic HTTP fetch framework.** New `pipeline/src/cholsey_pipeline/fetch/http.py::fetch_file`, the function every P2.3-P2.9 fetcher will call instead of hand-rolling its own download logic:
  - Retries transient failures (connection errors, HTTP 5xx) with exponential backoff, raising a clear `FetchError` after exhausting retries.
  - Real skip-if-unchanged: sends `If-None-Match`/`If-Modified-Since` from the previous manifest entry, so a server that supports conditional requests returns a genuine 304 with no body transferred — not just a re-fetch-then-compare. Falls back to a sha256 comparison for servers that ignore conditional headers (the manifest is still correct in that case, just not bandwidth-optimal).
  - Records sha256, byte size, `retrieved_at`, and writes a manifest entry to `data/manifest/<source_id>/<date>.json`, matching development-plan.md §2.2's target layout and the same pattern `geography/boundaries.py` already uses (Phase 1).
  - Network fully isolated behind an injectable `http_get` callable (same design pattern as `geography/boundaries.py`) — all 10 new tests run offline, including the exact idempotence test P2.2's "tests of success" asks for (fetching twice the same day writes one manifest entry and no new raw file).

## Decisions
- No new ADR — these are schema/framework implementation choices within an already-unblocked task (P2.1/P2.2 as literally specified in the plan), not scope/spec/stack decisions.
- Judgement call: kept `url` as the existing "landing/info page" field rather than renaming it to `landing_url` everywhere (would have been a much larger, purely-cosmetic diff across 17 entries with no functional benefit) — `download_url`/`download_urls`/`discovery_rule` are the new fields that actually matter for P2.2's fetcher to consume.
- Judgement call: implemented real conditional-request-based skipping (a genuine 304, no body transferred) rather than the simpler "download every time and compare hashes" approach — more faithful to P2.2's "skip the download if unchanged" wording, and it's what a well-behaved fetcher framework should do; the sha256-based fallback still covers servers that don't support conditional requests.
