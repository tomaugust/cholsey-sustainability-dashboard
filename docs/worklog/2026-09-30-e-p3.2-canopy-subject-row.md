## Done
- Checked Open questions first (plan §4.7): Q-005, Q-007, Q-011 still open, nothing new to action.
- **Real finding**: the plan's own wording ("check whether the ward is coterminous with the parish, use `method=direct` if so") needed a real check, not an assumption from the existing weight=1.0 row in `weights.csv`. Fetched both polygons live from the ONS Geoportal: Cholsey parish is ~15.91 km², Cholsey ward (E05011701) is ~65.96 km² -- over 4x larger. The parish sits wholly inside the ward (which is why P1.5's weight is 1.0), but the ward is a genuinely different, larger polygon -- not coterminous. So `method=direct` would have been wrong; this is `method=area_weighted`, always `flag=parish_estimate` (the Phase 1 PR review's own note, carried in STATUS.md's backlog, that a ward-level rate applied to a parish must say so, not be presented as parish-specific).
- Checked whether Forest Research or another source publishes a pre-aggregated district/England canopy figure directly (would have simplified district/national rows): no such aggregate found on Forest Research's own statistics pages. The `UK_Ward_Canopy_Cover` ArcGIS layer has a `country` field (could filter to England) but no LAD/district field, so a district figure needs a separate ward-to-LAD lookup, and an England figure needs pulling/aggregating all English wards -- both real, doable, but bigger pieces of work not attempted this firing.
- Built `pipeline/src/cholsey_pipeline/metrics/canopy.py`: `compute_subject_canopy_row(ward_record, ward_weight, parish_code, parish_name) -> CanopyMetricRow`, a pure function producing one row shaped to match `metrics.csv`'s schema (§2.3) once P3.9's export exists. Uses the real Cholsey ward record already in P2.3's committed fixture (E05009737, survyear 2021, 10.4% canopy cover) and the real weight ADR-0006 verified (99.4%).
