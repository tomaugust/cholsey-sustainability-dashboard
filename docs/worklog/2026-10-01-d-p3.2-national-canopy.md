# 2026-10-01 — P3.2's England national canopy row (ADR-0009)

- **Phase / tasks:** P3.2
- **Branch / PR:** `phase-3-metric-table` / not opened
- **Agent / person:** agent (routine firing)

## Goal

Build P3.2's last remaining gap: the England national row for tree
canopy cover, using real, live-verified Forest Research data, no guessed
values.

## Done

- Investigated the `UK_Ward_Canopy_Cover` service's schema live before
  writing any code: it has a `country` field (confirmed values Scotland/
  Wales/England/Northern Ireland) and, more importantly, its own `warea`
  field — a real ward area in m², verified against Cholsey's own ward
  record (66,557,077.88 m², matching the ~66 km² figure already used
  elsewhere in this codebase). This meant the national row didn't need a
  separate join against current ONS ward boundaries at all (unlike what
  STATUS.md's prior note anticipated) — Forest Research's own dataset is
  self-contained for area-weighting.
- `fetch/forest_research_canopy.py`: added `fetch_ward_canopy_for_country`
  — paginates `country='England'` live (6,135 records, maxRecordCount
  1,000 → 7 pages), writes its own merged manifest directly (same
  pattern as `geography.boundaries.fetch_boundary` for national-scale
  layers). `WardCanopyRecord` gained optional `country`/`ward_area_m2`
  fields (defaulting to `""`/`None`), unused by every existing subject/
  comparator/district call site.
- **Significant real finding, before writing the aggregate function**:
  summing all 6,135 English records' `warea` gives 71,286,265,097.85 m²
  — only **54.6%** of England's real area (130,462,331,610.03 m², the
  same `country_bfc` boundary P3.3's national greenspace row verified).
  By ward *count* the gap looks much smaller (6,135 of 6,862 current
  English wards, 89.4%) — meaning the missing ~727 wards are
  disproportionately large/rural, consistent with Aldworth's own
  containing ward (Basildon, West Berkshire) already having no Forest
  Research record at all (a P3.2 comparator-row finding from a prior
  firing). Also found live: wards were surveyed across real years
  2018-2023 (2,135 in 2020 alone, the modal year), not one single year;
  and 268 records (4.4%) carry a placeholder `survyear` of `0` with real
  `percancov`/`warea` but null `standerr`/`numpts`.
- Wrote **ADR-0009** documenting this and the decision: compute the
  national row from all 6,135 available records (including the 268
  placeholder-year ones, since their canopy/area measurements are real),
  label `year` with the modal real survey year (2020), and always set
  `flag=partial_coverage` (not `flag=none` like the district row) with a
  flag_note stating both coverage percentages and the likely urban bias.
- `contracts.py`: added a `forest_research_canopy_national` contract
  (same fields as `forest_research_canopy`, but doesn't require
  `standard_error`/`number_of_points` non-null, since 26 real England
  records legitimately lack them while still having valid
  `percent_canopy_cover`/`ward_area_m2`).
- `metrics/canopy.py`: added `compute_national_canopy_row` — unlike
  `compute_district_canopy_row`, does NOT require a single `survey_year`
  across records (a real difference from the district case, where South
  Oxfordshire's 21 wards happened to share one year); area-weights
  directly off each record's own `ward_area_m2`.
- Real figure: England's area-weighted average canopy cover across its
  6,135 available Forest Research ward records is **14.41%**.
- **P3.2 is now fully done** (subject+comparator+district+national) —
  and so are all three of P3.2/P3.3/P3.4, the three buildable core
  metrics apart from P3.5 (MCS-limited).

## Handoff notes

- Forest Research's `UK_Ward_Canopy_Cover` service's own `warea` field is
  a real, verified, directly-usable ward area — don't assume a national
  or large-scale aggregate from this dataset needs a separate ONS
  boundary join; check the service's own fields first (this firing did,
  via a live `?f=json` schema request, and found `warea` had already
  been quietly solving the national row's area-weighting problem).
- The ~54.6%-of-England coverage gap is a genuinely material limitation
  of this metric's national reference line — it is NOT simply "England's
  canopy cover," it's "the area-weighted average across the wards Forest
  Research happened to survey," which likely skews urban. If the
  dashboard's UI (Phase 5) ever shows this figure without surfacing
  `flag_note`, that would be a real regression against CLAUDE.md's
  "flag estimates" rule — make sure Phase 5's rendering actually reads
  and displays `flag`/`flag_note`, not just `value`.
