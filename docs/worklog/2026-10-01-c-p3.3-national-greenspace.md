# 2026-10-01 — P3.3's England national greenspace row

- **Phase / tasks:** P3.3
- **Branch / PR:** `phase-3-metric-table` / not opened
- **Agent / person:** agent (routine firing)

## Goal

Build P3.3's last remaining gap: the England national row for accessible
green space, using a real, live-verified England-wide OS Open Greenspace
clip (no guessed values, no silent interpolation).

## Done

- `geography/boundaries.py`: added a new `country_bfc` layer ("Countries
  (December 2023) Boundaries UK BFC"), found live via the same ONS
  ArcGIS org as the other boundary layers, not guessed. Confirmed live:
  England (E92000001) real area 130,462,331,610.02695 m².
- Fetched the full real OS Open Greenspace site set for England's bbox:
  150,817 sites (~550s live fetch).
- England's real BFC boundary polygon is far too complex to clip
  150,817 site polygons against directly (WKB 20,144,222 bytes) — a
  first attempt at `gpd.clip()` against the unsimplified boundary did
  not finish within a 30-minute background limit and was killed.
  Root-caused and fixed properly rather than just requesting a longer
  timeout: simplified the boundary (`shapely.simplify(tolerance=50.0,
  preserve_topology=True)`, reducing WKB to 928,430 bytes, ~21x
  smaller), then split the clip into two passes — a fast `.within()`
  classification against the simplified polygon (134,898 sites fully
  inside, no clip needed; 15,919 boundary-straddling candidates), then
  an exact `gpd.clip()` only on the much smaller candidate set (397
  clipped features). Completed in ~261s total. A 50m tolerance is
  immaterial at national-coastline scale for site-level greenspace
  polygons.
- Result: 96,914 accessible sites (ADR-0008 function types),
  1,940,711,368.3078492 m² accessible area, 1.4875645286709653% of
  England's real (unsimplified) area.
- England population: Census 2021, nomis, E92000001 = 56,490,048.
- `metrics/greenspace.py`: extracted `_build_greenspace_row` as the
  shared row-shaping logic (value, pct_of_area, flag/flag_note,
  geography_used) used by every `area_role`. Added
  `compute_national_greenspace_row`, which takes the pre-aggregated
  real accessible area directly rather than a `GeoDataFrame` — England's
  96,914-feature accessible-site set is far too large to commit as a
  test fixture, so (same idea as `LsoaEnergyRecord` carrying
  pre-aggregated totals rather than raw records) the national row is
  built from the already-computed real total. `compute_subject_greenspace_row`'s
  public signature and behaviour are unchanged (it now delegates to the
  same shared helper internally).
- `config/sources.yaml`: added the `ons_boundaries_country` entry for
  `country_bfc`, following the `ons_boundaries_lad` pattern, plus its
  real fetch provenance manifest
  (`data/manifest/boundaries/country_bfc/2026-10-01T05-12-52.440946+00-00.json`).
- Result: England **34.3549251065931 m²/resident**.

## Decisions

- No ADR needed — this doesn't introduce a new source or methodology
  choice, just applies the already-ADR-0008-decided accessible-type
  filter at national scale, and documents a reusable performance
  pattern (simplify + within/clip split) for any future national-scale
  geometry work in this pipeline (noted in `greenspace.py`'s module
  docstring and in `sources.yaml`'s `country_bfc` notes, not spun out
  as its own ADR since it's an implementation detail, not a
  methodology decision).
- Chose to represent the national row via a pre-aggregated-value
  function (`compute_national_greenspace_row`) rather than a proxy
  polygon or a committed partial fixture, since neither would add real
  test value over asserting the already-live-verified numbers directly,
  and a ~97,000-feature fixture is impractical to commit.

## Handoff notes

- The simplify + `.within()`/`gpd.clip()` split is the right default
  pattern for *any* future clip against a national-scale (or otherwise
  very detailed) boundary polygon in this pipeline — don't re-attempt a
  direct `gpd.clip()` against a full-precision England/GB boundary; it
  won't finish in a reasonable background-task time limit.
- The full England accessible-sites GeoPackage (96,914 features) and
  the full raw 150,817-site fetch are not committed anywhere (too
  large) — they only existed as scratch files in this session's
  container (`/tmp/england_greenspace_*.gpkg`) and are gone now. If a
  future session needs to re-verify or re-derive these numbers, it will
  need to re-run the same live fetch + simplify/clip pattern described
  above and in `greenspace.py`'s module docstring, not expect a cached
  file somewhere in the repo.
