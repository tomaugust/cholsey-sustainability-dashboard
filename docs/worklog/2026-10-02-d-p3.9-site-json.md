## Done

- **Corrected a wrong assumption from an earlier firing's STATUS.md

  real spec text, not the prior note's (incorrect) characterization.
- `export.py` gained:
  - `build_metrics_json(df)` -- groups `metrics.csv`'s rows by
    `metric_id`, keeping every column (the front end "never computes
    provenance, it only displays it," so each row stays fully
    self-describing).
  - `build_sources_json(df, sources)` -- only the `sources.yaml` entries
    actually cited by at least one row in `df`, not the full registry
    (several registered sources, like the stretch EPC source or the
    declined UKCEH alternative, aren't backing any real row yet) -- for
    the future methodology page (P4.7, "generated from `sources.json`").
  - `build_areas_json(geography)` -- the full `geography.yaml` registry,
    unfiltered.
  - `write_json(data, path)` -- a small writer. **Real bug found and
    fixed while building this**: `DataFrame.to_dict`/`.iterrows()` yield
    numpy scalar types (`numpy.int64`, `numpy.float64`), which
    `json.dumps` can't serialise at all -- raises `TypeError` -- a
    genuinely easy mistake to make. `_to_json_safe` converts each value
    via `.item()` (for numpy scalars) and turns pandas `NaN` into a real
    JSON `null` rather than the invalid `NaN` literal `json.dumps` would
    otherwise emit for a raw float NaN.
- `scripts/build_metrics_csv.py` now calls these and writes all three
  files after `metrics.csv`/`README.md`, in the same `main()` run.
- **Verification approach**: rather than re-running the full ~15-20
